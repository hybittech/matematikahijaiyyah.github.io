Reading the numbers
-------------------
1. hcpu_dataram dominates: 4096 words x 32 bits = 131,072 bits, inferred as
   flip-flops because the RTL describes a register array rather than a memory
   macro. This single module is ~87% of the design and was absent from the
   earlier hand estimate.

2. Excluding hcpu_dataram, the design is 64,630 cells — still 2.3x the ~28,200
   estimate, but the same order of magnitude.

3. Several estimate lines held up well: regfile (~15,000 vs 16,486), guard
   checker (~500 vs 609), UART (~200 vs 89). hcpu_rom was over-estimated
   (~2,000 vs 109) because it synthesizes as combinational logic, not storage.
   hcpu_codex_alu was under-estimated by ~3x.

4. Longest topological path: 84 logic levels, running through the divide- and
   modulo-by-10 at hcpu_top.v:193-194 (decimal conversion in the PRINT FSM).
   This is the critical path and is a timing concern, not an area one —
   hcpu_top is only 700 cells.

Caveats
-------
* No SKY130 PDK is installed, so these are generic-gate counts, not mapped
  standard cells, and no um^2 area or ns timing can be derived from this run.
  Cell counts are indicative of relative size only.
* Any die-area figure requires re-running with a liberty file
  (sky130_fd_sc_hd) and, for the memories, an SRAM macro.

Before a tape-out attempt
-------------------------
* Data RAM must become an SRAM macro (e.g. OpenRAM on SKY130) or shrink.
  131,072 flip-flops will not fit the 700x700 um user area in config.json.
  The same applies to hcpu_memory's 256x32 stack.
* Re-run against the real PDK to obtain area and timing closure.
